# Design, UX & Accessibility Audit — Jakbar Twogether

Date: 2026-10-28. Branch: `dev`. Status: findings only, no code changed. Awaiting approval.

## How this audit was done, and its limits

- **Static review** of every area in scope, split across three parallel reviewers (host live-session UI, member/auth/admin, marketing/SEO). I spot-checked the headline claims myself (no `error.tsx`/`loading.tsx`/`not-found.tsx` in `app/`; marketing layout calls `getCurrentUser()`; debug `console.log` in `app/sitemap.ts`).
- **Contrast** is computed from the oklch tokens in `app/globals.css` (OKLab → linear sRGB → WCAG ratio).
- **Live check, public pages only.** Measured in the real browser at 320 and 375px (via same-origin iframes), against `npm run dev` with the local Supabase at `127.0.0.1:54331`.
- **Live check, authenticated, with mutations (added after you approved it on the local DB).** Logged in as `host@jakbar.local` and `admin@jakbar.local` on the local Supabase. Ran the host flows end to end (start session, check in, courts, manual and auto matches, complete, cancel participant), simulated a dropped connection, and exercised an admin role change. Results are tagged "(live)" in the tables and collected in section 2b.
- **Not done live (marked Unverified where relevant):**
  - **Chrome DevTools MCP:** `emulate` and `lighthouse_audit` both fail with a CDP error (`Network.emulateNetworkConditionsByRule … params.offline`). The window also cannot go below 500px. So there is no Lighthouse, no Core Web Vitals, no Slow-3G/offline run, and no landscape/768/1024 sweep. Dev-server numbers would not be representative of production anyway.
  - **Production-like performance:** everything live was measured against `next dev`, so latencies (for example 2.4–4s per check-in) are inflated by dev mode and the local round trip. Treat them as relative.
- Screenshot evidence: `docs/design-audit/screens/landing-375.png` and `docs/design-audit/screens/manage-matches-375.png`.
- The Next.js 16 docs in `node_modules/next/dist/docs/` were consulted only by the marketing reviewer. The host reviewer explicitly made no Next-16-specific claims.

### Top 5 problems

*(Most are now confirmed live; see section 2b. One new high-severity item, L-02, is auto-match silently failing because host-set gender is hidden by the consent gate.)*

1. **Realtime is not trustworthy courtside (H-02, H-01).** The "Live" badge is a static green dot. The watcher ignores subscribe status and never refetches on `online`/`visibilitychange`. Action handlers have no try/catch and there is no error boundary. A locked or offline phone shows stale courts with a "Live" badge.
2. **Destructive host actions are one tap with no confirm or undo (H-04, H-13).** Roster Cancel (fires waitlist promotion), court Delete, match Cancel and match Complete. `design.md` promises an Undo toast that was never built.
3. **Times render in the wrong zone and locale (X-01).** `toLocaleString()` with no `timeZone` in Server Components shows UTC/en-US, about 7 hours off for Jakarta. Marketing and WhatsApp code pin `Asia/Jakarta`, so the two halves disagree.
4. **AA contrast and target-size failures at the token/primitive level (X-02, X-03).** The fix is in `globals.css`, `button.tsx`, `input.tsx`, `select.tsx`, `dialog.tsx`, so it propagates everywhere.
5. **No error, loading or not-found states, and no password reset (X-04, M-03).** Zero `error.tsx`/`loading.tsx`/`not-found.tsx` in `app/`. Members who forget a password are locked out unless Google matches.

## 3. Flow walkthrough notes

Tap counts are from code unless noted. `(app)` flows were not clicked live.

**Member**
- Sign up (email): open `/signup`, type 4 fields (name, email, phone, password), 1 tap Sign up, then follow the email link, which lands on `/dashboard`. Dead ends: no resend (M-02), no password-rule hint before failure (M-03).
- Sign up (Google): 1 tap plus Google consent. Phone is never collected (M-05).
- Log in: 2 fields plus 1 tap. Forgot password is impossible (M-01).
- Find a session: Sessions in the nav (1 tap, may need horizontal scroll, M-07), then a card (1 tap) = 2 taps.
- Register: about 3 taps including nav. Cancel: 3+ taps; the dashboard card has no cancel action. Both counts are from code, not clicked.
- Failure state: on a bad connection the register panel shows "Register" to someone already registered (H-11).
- History: 1 tap, plus 1 per match.

**Host (session management)**
- Create session: nav "New session" (1) plus a long form. The Edit dialog clips on phones (H-03).
- Start session: 1 tap, no confirm. Close or Cancel session: 3 taps with a proper confirm (good).
- Add participant: 3–5 taps. Replace seat: 3. Copy WhatsApp text: 2 (good).

**Host (live session)**
- Check in a player: **1 tap** (roster is the default tab). No search or filter, so finding a name means scrolling. Every tap disables every other button until it returns (H-07).
- Cancel a participant: 1 tap, no confirm, no undo (H-04).
- Create a match (manual): court select 2, players 4, Create 1 = 7 taps, plus 1 to Start = **8 taps** (+1 if switching tab), plus about 1,760px of scroll past two copies of the queue (H-05).
- **Finish a match and start the next (manual): 9 taps.** Complete is one tap and not undoable (H-08).
- Auto path: Generate 1, Confirm all 1, Start 1 per court = 3 taps plus 1 per match. Confirm all only schedules; there is no "confirm and start". +2 per manual swap.
- Checked-in pool vs registration list: separate for matching (good), but visually weak on the roster (H-06).
- Race behaviour: the realtime refresh keeps selections but never prunes stale players (H-10). Two hosts or a member cancelling mid-edit are only caught by the server rejecting after the tap.

**Admin**
- Change role: 3 taps, no confirm (M-09). Grant membership: about 7 taps, no member search. Create plan: 2. Cancel membership: one 600ms hold (not operable via TalkBack, M-10).
- FAQ edit: Edit, fields, save (2 taps). Reorder: one tap per step, no drag.
- Content (about/FAQ/gallery) all lives on one long `/admin` page (M-11).

## 4. What's working well (don't undo)

- Roster collapses to stacked cards on mobile with `h-11` buttons. ManageTabs has `min-h-11` tabs with counts and keeps panels mounted so selections survive a tab switch or refresh.
- The checked-in pool is a real separate concept: `lib/dal/rotation.ts` builds the queue from confirmed + checked-in + not busy. Matches go through RPCs (`create_match`, `start_match`, `complete_match`).
- Manual override is everywhere: roster status buttons, the manual match builder alongside auto-match, swap/discard in auto-match, and the coach-count dialog that explains the promotion effect.
- Session cancel/close have real confirm dialogs with consequence copy and pending labels. Start/Add/Replace/Save show pending text; `SessionForm` blocks double submit.
- Status badges always carry text (Confirmed/Waitlist/In progress), not colour alone. `aria-pressed` on slot and replace buttons; coach +/- have `aria-label` and `aria-live`.
- Shared-zod validation client and server; field errors wired with `aria-describedby`/`aria-invalid`; autocomplete values on every auth field.
- Auth security: `safeNext` hardening, OTP type allowlist, enumeration-safe wording.
- HoldToConfirmButton: keyboard support, `aria-live` countdown, reduced-motion fallback. Admin dialogs use `max-h-[90vh] overflow-y-auto`. Gallery admin: 44px targets, labelled icon buttons, motion-reduce guards.
- Gallery and lightbox: Radix focus trap/Escape/restore, arrow keys, 44px controls, `next/image` with `sizes`, scoped `remotePatterns`, pinned `Asia/Jakarta` dates.
- Sitemap and robots with localized alternates. FAQ JSON-LD (escaped). `next/font` self-hosted. en/id message key parity is 100%.
- 320px-safe layout: no horizontal overflow measured on `/en`, `/en/sessions`, `/en/gallery`, `/en/about`, `/en/faq`, `/login`, `/signup`. Light-theme ink/paper 16.6:1 and muted/paper 6.0:1 pass.
- Clipboard write keeps the iOS user gesture (`session-actions-menu.tsx:57-80`).

## 6. Five changes that would most improve a host's live-session experience

1. **A real connection indicator with refetch on reconnect (H-02), plus error handling on every action (H-01).** Hosts must know whether what they see is current.
2. **Undo for roster Cancel and match Complete/Cancel, and confirm for court Delete (H-04, H-08).** One mis-tap currently fires waitlist promotion or frees a live court with no way back.
3. **Matches tab: live matches first, one queue list with a team toggle (H-05).** Cuts about 1,760px of scroll above Complete/Start and shortens the 9-tap "finish and start next".
4. **44px touch targets at the primitive level, and the dialog scroll fix (X-03, H-03).** Fixes Actions menu, Add participant, dialog footers, selects and Edit session in one pass.
5. **Per-row pending states, a "Checked in" chip, and a filter/search on the roster (H-07, H-06).** Check-in is the most frequent action, and today it serialises on slow signal and is hard to scan.
