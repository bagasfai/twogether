# CI Pipeline Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A GitHub Actions workflow that runs every test suite on each push to `dev` and on each pull request into `main`, plus Vercel and docs changes so that a green merge into `main` is the only route to production.

**Architecture:** One workflow, `.github/workflows/ci.yml`, with two parallel jobs. `checks` runs lint, types, Vitest and `next build` with no database. `db-and-e2e` boots the local Supabase stack (send-email hook off), then runs pgTAP, the race scripts and Playwright. Two small shell helpers under `scripts/ci/` do the stack-specific setup so they can be tested on a dev machine. `vercel.json` limits Vercel builds to `main`.

**Tech Stack:** GitHub Actions (ubuntu-latest), Node 22, Supabase CLI 2.117 (devDependency, `npx supabase`), pgTAP, bash + psql, Playwright Chromium, Vercel Git integration.

**Spec:** `docs/superpowers/specs/2026-11-17-ci-design.md`

## Global Constraints

- No secrets in the workflow. The repo is public, so fork pull requests run it. Every credential comes from the stack CI boots.
- Triggers: `push` to `dev`, and `pull_request` with base `main`. Concurrency group per ref, `cancel-in-progress: true`.
- Node 22, `npm ci`, npm cache through `actions/setup-node`.
- Job ids and display names are exactly `checks` and `db-and-e2e`. Branch protection refers to them by name.
- CI never talks to the hosted Supabase project or to Resend.
- The send-email hook is turned off only in the CI working copy. The committed `supabase/config.toml` is unchanged.
- Pin each action to its current major version; check each action's README when writing the file.
- Change `ARRIVAL_SPREAD_THRESHOLD_MS` in CI only if `test-concurrent-registration.sh` actually fails on the barrier-spread assertion on a runner.
- No explanatory comments beyond what the repo's shell scripts already do (a short header saying what the script proves or does).

## Review Focus

1. **The hook rewrite hits the wrong `enabled`.** `config.toml` has many `enabled = true` lines. Only the one directly under `[auth.hook.send_email]` may change. Task 1's test asserts that exactly one line differs.
2. **Missing key in `supabase status -o env` output.** If the CLI renames a key (for example `ANON_KEY`), the env script must fail loudly instead of writing an empty value. Task 1's test covers a missing key.
3. **A failed `supabase start` reported as test failures.** If the stack doesn't boot, the test steps must be skipped, so the failure points at the boot step. Task 3 gates the test steps on the start step's outcome.
4. **One red suite hiding the others.** pgTAP failing must not skip the race scripts or Playwright. Task 3 uses `!cancelled()` plus the start-step outcome on each test step.
5. **`next build` silently querying a database at build time.** Task 2 runs the build locally with the same dummy env CI uses, and keeps the result as evidence.

### Task 1: CI helper scripts

**Files:**
- Create: `scripts/ci/disable-send-email-hook.sh`, `scripts/ci/write-env-local.sh`, `scripts/ci/test-ci-helpers.sh`

**Interfaces:**
- Produces: `scripts/ci/disable-send-email-hook.sh <toml-path>` edits the file in place. It exits non-zero if the block or its `enabled = true` line is not found.
- Produces: `scripts/ci/write-env-local.sh <out-path>` writes these keys:
  - `NEXT_PUBLIC_SUPABASE_URL` (from `API_URL`)
  - `NEXT_PUBLIC_SUPABASE_ANON_KEY` (from `ANON_KEY`)
  - `SUPABASE_SERVICE_ROLE_KEY` (from `SERVICE_ROLE_KEY`)
  - `NEXT_PUBLIC_SITE_URL=http://127.0.0.1:3000`
  - `INQUIRY_IP_SALT=ci-not-secret`

  It exits non-zero, writing nothing, if any source key is missing or empty. For tests, `SUPABASE_STATUS_ENV` (path to a file) replaces the `supabase status` call.

- [ ] **Step 1: Write the failing self-test** `scripts/ci/test-ci-helpers.sh` (bash, `set -euo pipefail`, works in `mktemp -d`, prints `PASS: <name>` per case, exits 1 on the first failure):
  - `hook_only_block_changes`: copy `supabase/config.toml`, then run the disable script. `diff` must show exactly one changed line, and inside the `[auth.hook.send_email]` block the line must read `enabled = false`.
  - `hook_missing_block_fails`: a TOML with no `[auth.hook.send_email]` block makes the script exit non-zero.
  - `env_writes_all_keys`: a fake status file with `API_URL="http://127.0.0.1:54331"`, `ANON_KEY="anon"` and `SERVICE_ROLE_KEY="svc"`. The output file must contain exactly these 5 lines:

    - `NEXT_PUBLIC_SUPABASE_ANON_KEY=anon`
    - `SUPABASE_SERVICE_ROLE_KEY=svc`
    - `NEXT_PUBLIC_SITE_URL=http://127.0.0.1:3000`
    - `INQUIRY_IP_SALT=ci-not-secret`
  - `env_missing_key_fails`: a status file without `SERVICE_ROLE_KEY` makes the script exit non-zero, and no output file is created.

### Task 2: Prove `next build` works without a database

**Files:** none changed unless the build fails.

- [ ] **Step 1: Build with the CI env**

Run, from the repo root:
```bash
NEXT_PUBLIC_SUPABASE_URL=http://127.0.0.1:59999 \
NEXT_PUBLIC_SUPABASE_ANON_KEY=ci-dummy \
SUPABASE_SERVICE_ROLE_KEY=ci-dummy \
NEXT_PUBLIC_SITE_URL= \
npm run build
```
`NEXT_PUBLIC_SITE_URL=` is set to empty on purpose. Process env wins over `.env.local`, and an empty value makes `getSiteUrl()` return `null`, so `app/sitemap.ts` skips its queries. The other keys override the local values the same way.

Expected: the build succeeds, with no `ECONNREFUSED` in the output.

- [ ] **Step 2: Record the outcome.** If it passed, Task 3 keeps `npm run build` in `checks` with exactly these four env values. If it failed on a page that queries at build time, move `npm run build` into `db-and-e2e` after `supabase start`, and report which page caused it. Either way, put the outcome in the Task 3 commit message body.

### Task 3: The workflow

**Files:**
- Create: `.github/workflows/ci.yml`

**Interfaces:**
- Consumes: Task 1's two scripts (by path), Task 2's env values.
- Produces: check names `checks` and `db-and-e2e` (Task 6's owner steps use them).

- [ ] **Step 1: Write `ci.yml`**
  - `on.push.branches: [dev]` and `on.pull_request.branches: [main]`.
  - `concurrency: { group: ci-${{ github.ref }}, cancel-in-progress: true }`.
  - `permissions: contents: read`.

  **Job `checks`** (`name: checks`, `timeout-minutes: 15`):
  1. checkout, then setup-node (`node-version: 22`, `cache: npm`), then `npm ci`.
  2. `npm run lint`.
  3. `npx tsc --noEmit`.
  4. `npm run test:unit`.
  5. `npm run build`, with the job-level `env` from Task 2.

  **Job `db-and-e2e`** (`name: db-and-e2e`, `timeout-minutes: 40`):
  1. checkout, then setup-node (`node-version: 22`, `cache: npm`), then `npm ci`.
  2. `scripts/ci/disable-send-email-hook.sh supabase/config.toml`.
  3. Step `id: start`, `npx supabase start -x studio,postgres-meta,imgproxy,logflare,vector,supavisor,edge-runtime`. Job-level env `SEND_EMAIL_HOOK_SECRET: v1,whsec_Y2ktbm90LXNlY3JldC1ob29rLWtleS0wMDAwMDA=`, a throwaway value that is not a secret. Mailpit, realtime, storage, gotrue, postgrest and kong stay on.
  4. `npx supabase test db`.
  5. A loop over `scripts/test-concurrent-*.sh scripts/test-public-community-stats.sh`. Run each script, record a failure, continue to the next, and exit 1 at the end if any failed. Print `== <script>` before each one.
  6. `scripts/ci/write-env-local.sh .env.local`.
  7. `npx playwright install --with-deps chromium`.
  8. `npm run test:e2e`.
  9. On `failure()`, upload `test-results/` (traces) as artifact `playwright-traces`, kept 7 days.

  Steps 4, 5, 6 and 8 each carry `if: ${{ !cancelled() && steps.start.outcome == 'success' }}`.

Run: `docker run --rm -v "$PWD:/repo" -w /repo rhysd/actionlint:latest -color`
Expected: no output, exit 0. Shellcheck findings inside `run:` blocks count too; fix them.
